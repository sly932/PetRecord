# UX 设计与导航决策

## 1. 主要界面
- 主页（宠物列表）：展示所有宠物卡片，支持新增宠物
- 宠物档案详情：展示姓名、性别、品种、生日、当前体重摘要、驱虫概览
- 体重面板（单宠）：体重记录列表 + 趋势图（Swift Charts）+ 新增记录
- 驱虫面板（单宠）：驱虫记录时间轴 + 新增记录
- 所有宠物体重面板：以卡片或对比图展示多只宠物的体重趋势入口

## 2. 导航与跳转
```mermaid
graph TD
  Home[主页/宠物列表]
  Pet[宠物档案详情]
  W1[体重面板(单宠)]
  D1[驱虫面板(单宠)]
  WAll[所有宠物体重面板]

  Home -->|点某只宠物| Pet
  Pet --> W1
  Pet --> D1
  Home --> WAll
  W1 -->|查看更多宠物| WAll
  WAll -->|点某宠物| W1
```

## 3. 体重面板的设计取舍（核心问题）
- 方案A：在“档案详情”里直接内嵌完整体重模块
  - 优点：集中；缺点：页面过重、重复逻辑与视图状态
- 方案B（推荐）：独立“体重功能面板”，档案中仅做概览与入口
  - 优点：单一职责、复用性高、测试与维护更容易
  - 实施：档案→跳转到 W1；WAll→点某宠物→跳转到同一个 W1

## 4. 信息架构与组件切分
- 档案详情：顶部基本信息区；中部概览卡片（当前体重、最近驱虫）；底部进入各功能面板的入口
- 体重面板：
  - 顶部：日期范围筛选（周/月/年）
  - 中部：折线/点线图（Swift Charts）
  - 底部：记录列表 + 新增按钮
- 驱虫面板：
  - 顶部：下一次建议时间（可选）
  - 中部：时间轴列表
  - 底部：新增按钮

## 5. 是否需要 Figma/Canva 原型
- 小团队/个人项目建议：
  - 先画 4–5 张低保真线框（Figma），锁定导航、布局与信息密度
  - 随后直接在 SwiftUI 做交互原型（边实现边微调）
- 何时可省略 Figma：
  - 页面较少、你对 SwiftUI 布局把握足够时；但至少先在纸上勾勒结构

## 6. 交互与可用性要点
- 可访问性：动态字体、对比度、VoiceOver 标签
- 表单校验：体重>0、日期默认今天；错误提示明确
- 删除与撤销：敏感操作提供确认或“撤销”提示
- 空状态：无数据时展示指引文案与“添加”入口
